## 技术前提

Phase 2 的核心能力依赖 **Android Accessibility Service（无障碍服务）**，这是 Android 系统提供的标准 API，允许 App 读取屏幕内容、模拟点击和输入，无需 root 权限。

### 所需底层能力

| 能力 | 说明 | 依赖 |
|------|------|------|
| App 启动 | 通过 Intent 或包名启动第三方 App | ✅ Android API 已有 |
| 屏幕内容读取 | 获取当前屏幕的 UI 元素树（节点、文本、坐标） | 需无障碍服务 |
| 模拟触控 | 在指定坐标执行点击、长按、滑动 | 需无障碍服务 |
| 文本输入 | 向输入框填入文字 | 需无障碍服务 |
| 视觉理解 | 对屏幕截图进行 AI 多模态分析，判断当前界面状态 | 依赖 Gateway 多模态模型 |
| 动作编排 | 将复杂任务拆解为"观察→判断→操作"循环 | AI Agent 层面实现 |

## 应用场景

### 场景 1 — 智能打车

**目标**: AI 可自动打开打车 App，完成从叫车到确认的全流程

**典型流程**:
1. 用户说"帮我叫辆车去xxx"
2. AI 打开滴滴出行或高德地图
3. 读取屏幕确认 App 就绪
4. 输入目的地地址
5. 选择车型（快车/专车/拼车）
6. 确认叫车
7. 返回叫车结果给用户

**涉及 App**: 滴滴出行、高德地图

### 场景 2 — 点外卖

**目标**: AI 可自动打开外卖 App，完成搜索、选店、下单

**典型流程**:
1. 用户说"帮我点一份xxx"
2. AI 打开美团或饿了么
3. 搜索指定店铺或菜品
4. 选择商品和规格
5. 确认订单信息
6. 跳转支付
7. 返回下单结果

**涉及 App**: 美团、饿了么

### 场景 3 — 智能路线规划

**目标**: AI 可自动规划出行路线，展示给用户

**典型流程**:
1. 用户说"从A到B怎么走"
2. AI 打开地图 App
3. 输入起点和终点
4. 选择出行方式（驾车/公交/步行）
5. 预览路线方案
6. 返回路线信息给用户

**涉及 App**: 高德地图、百度地图

### 场景 4 — 生活服务（扩展方向）

| 场景 | 涉及 App | 说明 |
|------|---------|------|
| 订酒店 | 携程、飞猪 | 搜索、筛选、预订 |
| 购物比价 | 淘宝、京东、拼多多 | 搜索商品、比较价格 |
| 生活缴费 | 支付宝、微信 | 缴费、账单查询 |
| 票务预订 | 猫眼、大麦 | 选座、购票 |

## 技术挑战与应对

| 挑战 | 说明 | 应对方案 |
|------|------|---------|
| App UI 变化 | 第三方 App 更新后界面元素位置可能改变 | 基于语义匹配而非固定坐标 |
| 登录态 | 部分 App 需要登录才能操作 | 首次手动登录，后续维持态 |
| 验证码/滑块 | 部分操作有人机验证 | 需人工介入或 AI 视觉识别 |
| 多步骤失败回滚 | 中间步骤失败后需回退重试 | 编排引擎支持重试和回滚 |

## 边界约定

- 首批聚焦高频场景（打车、外卖、导航），生活服务等后续扩展
- 支付环节涉及资金安全，建议首次由用户手动确认
- 部分 App 可能因反自动化检测拒绝操作，需持续适配
- AI 技术持续演进，本 spec 将动态调整
